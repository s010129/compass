# 轉盤向心力感測器

手機螢幕朝上平放在旋轉桌（轉盤）上，用內建加速度計把水平方向的加速度即時分解成
**向心分量（紅色箭頭，指向圓心）** 與 **切線分量（綠色箭頭，沿速度方向）**，
兩個箭頭的長度都正比於各自的大小。概念參考 phyphox 的向心加速度實驗。

可安裝的 PWA，離線可用，圖示是 Minecraft 風格的羅盤（指針會指向圓心方向）。

## 怎麼用

1. 手機螢幕朝上平放在轉盤上，**靠外緣**並固定好（a_c = ω²r，放圓心上量不到東西）。
2. 按 **開始測量**，再按 **校正方向**，照提示做：
   **先讓轉盤靜止 → 轉起來 → 保持等速轉三圈**。
3. 校正完圓心方向與旋轉方向就鎖定了，之後即時顯示。
4. 按 **匯出 CSV** 取得原始資料（含瞬時值與每圈平均）。

沒有手機在手邊時，按 **示範模式** 會模擬一個含 2° 桌面傾斜的轉盤。

## 兩種視角

畫面上方可切換，**同一份資料、兩個參考系**：

- **螢幕視角**：手機自己的座標系。手機固定在中央，圓心方向不動（手機跟著轉盤轉，
  圓心相對於手機的方向本來就固定）。灰色箭頭是未平均的瞬時值——
  **灰箭頭繞圈、紅箭頭不動，那個繞圈幅度就是重力洩漏**，可直接當教材。
- **鳥瞰視角**：房間的座標系。手機繞著圓心跑，藍色弧線是走過的軌跡。

兩個視角的箭頭長度完全一樣（a_c 與 a_t 的大小與參考系無關，兩者只差一個旋轉）。

鳥瞰視角的轉動用**陀螺儀的 |ω| 積分**驅動，不用 `deviceorientation` 的方位角：
方位角在 Android 是磁力計絕對值（轉盤的金屬軸承／馬達磁鐵會干擾），
在 iOS 是相對值且會持續漂移。另外 canvas 的 y 軸向下，螢幕上的逆時針對應
canvas 角度**遞減**，直接把角度加上去會讓畫面轉向和實際相反。

## 為什麼一定要先校正

轉盤平面只要沒有完全水平，重力就會漏 `g·sinθ` 進水平面。而**手機跟著轉盤轉、
重力卻固定在房間裡**，所以這個洩漏向量在裝置座標中**每轉一圈就繞一圈**，
向心加速度卻是不動的：

```
h(t) = a_c·ĉ + a_t·t̂ + g·sinθ·(以 −ω 旋轉的單位向量)
       └── 直流 ──┘   └────── 頻率 ω 的正弦 ──────┘
```

歸零校正扣不掉它（那只能扣常數偏移），一般低通也濾不掉。實測影響：

| 轉盤傾斜 | 轉速 | 洩漏 vs 向心 | 圓心方向誤差 |
|---|---|---|---|
| 0° | 28 rpm | 0 vs 1.03 | 0° |
| 2° | 28 rpm | 0.34 vs 1.03 | ±15° |
| 4° | 15 rpm | 0.68 vs 0.30 | **269°（整個轉一圈）** |

而手機本身是貼平的，`f_z` 完全看不出異常，所以傾斜警告不會觸發。

**唯一乾淨的解法是對整數圈取平均** —— 正弦在整數週期上積分恰好為零。所以校正
要轉滿三圈：平均值給出圓心方向，殘差就是洩漏本身，其振幅可反推轉盤傾斜角。
即時顯示也一直維持「最近一整圈」的移動平均。

取樣必須等轉速穩定才開始（容差 ±6%）—— 加速中 a_c 一路長大、a_t 又不是 0，
平均值會被切線分量拉歪，殘差也會被 a_c 的變化蓋過。摩擦造成的緩慢衰減遠在容差內。

校正後的模擬驗證（真值已知）：

| 轉盤傾斜 | 轉速 | | 圓心方向擺動 | a_c | r |
|---|---|---|---|---|---|
| 4° | 15 rpm | 未校正 | 15° | 0.28（真值 0.30） | 0.114（真值 0.12） |
| 4° | 15 rpm | **已校正** | **0.0°** | **0.30** | **0.121** |
| 2° | 28 rpm | **已校正** | **0.0°** | **1.04**（真值 1.03） | **0.12** |

## 方向是怎麼定出來的

裝置座標為 **+x 螢幕右、+y 螢幕上、+z 穿出螢幕**。

- **正負號慣例**：平放螢幕朝上時 Android `accelerationIncludingGravity.z ≈ +9.8`、
  iOS ≈ −9.8。由 z 軸自動判定，慣例確定前不做任何計算。
- **向心方向**：修正後水平分量就等於真實加速度的水平分量（重力只有 z 分量），
  方向指向圓心。校正時對整數圈取平均後鎖定。
- **旋轉方向也是純加速度計判定的**：房間裡固定的向量在裝置座標中以 −ω 旋轉，
  所以看校正時重力洩漏往哪邊繞，轉盤就是相反方向。切線 t̂ = (ĉ_y, −ĉ_x)（ω > 0 時）。
- **陀螺儀只用來取 |ω|**（大小，與正負號慣例無關），供計算轉速、半徑與圈數。
  所有方向都不依賴陀螺儀。
- **不顛倒**：canvas 的 y 軸向下、裝置 +y 向上，繪圖時對 y 取負號；
  另用 `screen.orientation.angle` 補償橫豎屏。
- **推算值**：`r = a_c / ω²`、`v = ω·r`，兩者都取同一個平均窗內的量，
  否則轉速在變時會拿不同時刻的值相除。
- **手機傾斜 vs 轉盤傾斜**：前者由 `f_z = g·cosθ` 算出（手機沒貼平，超過 10° 示警）；
  後者整個平面沒水平、手機仍貼平，`f_z` 看不出來，只能從校正的洩漏振幅反推。

## iOS 與 Android 的差異

| 項目 | Android | iOS | 程式怎麼處理 |
|---|---|---|---|
| 加速度計正負號 | 平放 z ≈ +9.8 | 平放 z ≈ −9.8 | 由 z 軸自動判定 |
| 陀螺儀正負號 | 不保證一致 | 不保證一致 | 只取 \|ω\|，方向完全不依賴它 |
| 權限 | 不需額外授權 | 手勢 + 系統設定 | 以「開始測量」觸發 `requestPermission()` |
| 取樣率 | 各機種不同 | 約 60 Hz 上限 | 狀態列顯示實際值 |
| HTTPS | 必要 | 必要 | — |

## 檔案

```
index.html              頁面
styles.css              樣式
src/app.js              量測、分解與繪圖
src/mc-compass.js       Minecraft 風格羅盤的像素畫產生器（瀏覽器與 icon 共用）
tools/gen-icons.mjs     產生 PWA icon（node tools/gen-icons.mjs，無外部相依）
manifest.webmanifest    PWA manifest
sw.js                   Service worker（離線快取）
```

重新產生 icon：

```sh
node tools/gen-icons.mjs
```

改動程式碼時，把 `src/app.js` 的 `BUILD` 和 `sw.js` 的 `VERSION` 一起往上跳，
版本號會顯示在頁尾，方便確認手機上跑的是哪一版。程式碼類的檔案走 network-first，
所以有網路時一定拿到最新版；圖檔維持 cache-first。

在瀏覽器主控台打 `__state` 可以看到所有內部估計值（圓心方向、陀螺儀正負號、
傾斜角等），方便除錯。

所有運算都在手機端完成，不會上傳任何資料。
